# Live checks for Website Studio v2

Everything below was built from the APEX 26.1 metamodel and checked in the QA harness. The harness renders the real `.apx` templates with Universal Theme 26.1 and Chromium. These points still need a real APEX 26.1 instance. Each one names the generator to change if it fails; the generated `.apx` line is given for reference.

## 1. Import

- [ ] `apex import -input apexlang` runs without errors. The files that are new in v2 are:
  - `pages/p00011-company.apx` to `p00017-saas.apx`
  - `shared-components/lists.apx` (now generated)
  - `list-templates/website-menu.apx`
  - nine new report templates
  - the `WHATSAPP_NUMBER` substitution in `application.apx`
- [ ] **List region type.** The menu region is written as `type: list` with `source { list: @... }` and `componentAppearance { listTemplate: @website-menu }`.
  - Generated: `apexlang/pages/p00010-website.apx:1634`
  - Generator: `apexlang/_src/pages.mjs:96` (`menuRegion`)
  - I took `list` from the plugin name `NATIVE_LIST` and from theme.apx's `list:` default. No 26.1 example with a list region was available.
- [ ] **List template.** `templateClass: pullDownMenu` and `#LINK_ATTR#` in the entry templates (`list-templates/website-menu.apx:3`, `:9`). Generator: `apexlang/_src/build.mjs` (listTpl).
- [ ] **SQL list.** The restaurant menu uses `source { type: sqlQuery }` with a `connect by` query.
  - Generated: `apexlang/shared-components/lists.apx:529`
  - Generator: `apexlang/_src/pages.mjs:334` (`sqlList`)
  - Check that the drop-down shows Starters, Mains and Desserts under Menu.
- [ ] **List entry user attribute 2 and link attributes.** External entries carry `userDefinedAttributes { 2: _blank }` and `linkAttributes: rel="noopener"` (`lists.apx:348-351`). Check that "Journal" on page 10 opens in a new tab.
- [ ] **Page HTML Header.** The `htmlHeader { htmlHeader: ... }` block is at `p00010-website.apx:16`, generated by `pages.mjs:171` (`htmlHeader`).
- [ ] **Honeypot item.**
  - `layout { columnCssClasses: ws-Honeypot }` and `advanced { customAttributes: tabindex="-1" autocomplete="off" }` (`p00010-website.apx:2231`, `:2238`, from `pages.mjs:145`).
  - The field must be invisible and the form must still submit.
  - With a value in `P10_WEBSITE`, the process must do nothing (`p00010-website.apx:2272`).

## 2. In the browser

- [ ] **Substitutions in the HTML Header.** `#APP_FILES#` inside `og:image` and `<link rel="preload">` should become the application's file URL (`p00010-website.apx:23-25`). If it stays literal, the preload is harmless but `og:image` needs a full URL.
- [ ] **IMAGE_FILE.** The body carries `data-ws-files="#APP_FILES#"` (`modern-one-page.apx:30`), and `website.js` (`_src/website.js:131`, `appFiles`) prefixes `IMAGE_FILE` with it. If APEX leaves `#APP_FILES#` unsubstituted on the body tag, the script falls back to the folder `website.css` was loaded from. Check that a photo appears after the photos are downloaded (see 4).
- [ ] **Menu slot.**
  - The Website - Menu list renders in `REGION_POSITION_08` (`modern-one-page.apx:41`) and `website.js` moves it into the header (`_src/website.js:501`, `menu`).
  - Check desktop drop-downs (hover, click, ArrowDown, Escape), the phone accordion, the "More" overflow on page 11 (5 visible entries), the overlay on page 14 and the drawer on page 13.
- [ ] **Current entry.**
  - APEX may mark a list entry current by page. The script clears that for `#anchor` entries and marks the section on screen instead.
  - In the studio's side navigation, check "Starter Websites" and its children (`lists.apx:85`).
- [ ] **Arabic page.**
  - Page 13 sets `dir="rtl"` and `lang="ar"` from its HTML Header (`p00013-clinic.apx:22`), and on the body once the page has loaded. This matters because `#TEXT_DIRECTION#` on the body could write `dir="ltr"` in an English application.
  - Check that the header, slider arrows, drawer, WhatsApp button and back-to-top are mirrored, and that the texts "القائمة", "المزيد" and so on appear (`_src/website.js:21`).
- [ ] **WhatsApp button.** `&WHATSAPP_NUMBER.` in the page template (`modern-one-page.apx:60`). The value is set in `application.apx:59`; replace `966500000000` with the real number. The button shows only with the *WhatsApp Button* option (page 13).
- [ ] **Light/dark toggle** (pages 13 and 17): the choice survives a reload (localStorage `ws-scheme`).
- [ ] **Designer.**
  - The website picker loads `f?p=&APP_ID.:<ALIAS>:&APP_SESSION.` in the preview. Check every site loads; the pages are public.
  - Section options act on every region of a template through the URL hash `r=@ws-hero:...`.
  - Check that *Copy APEXlang* and *Copy SQL* copy. The clipboard needs https.
- [ ] **Gallery.** The site thumbnails `gallery/site-*.jpg` and the 27 look thumbnails show, and *Open Website* opens each page.
- [ ] **Contact forms.** Required fields show APEX's error styling inside the Modern Section. The success message shows after *Send*.

## 4. Photos (not downloaded yet)

The build sandbox could not reach Unsplash or any other photo host: the proxy answers 403. So the 56 photos named in `apexlang/_src/photos.mjs` are not in the repository yet, and every website shows its placeholder images.

- [ ] Run `node tools/fetch-photos.mjs` on a machine with internet access. It tries each photo id in order and keeps every file within its size limit (5 MB budget in total). It then rewrites `docs/CREDITS.md` with the source and licence of each photo.
- [ ] Run `cd apexlang && node _src/build.mjs` to list the photos in `static-files.apx`, then run `node _src/pages.mjs` and `node qa/thumbs.cjs` to refresh the Gallery thumbnails with photos. Import again.
- [ ] Look at each starter website. The photo ids were chosen from memory of Unsplash's library. If one shows the wrong subject, change its id in `photos.mjs` and run the script with `--force`.
- [ ] Check that the hero text stays readable on every photo. Use the *Image Overlay* option or `IMAGE_POSITION` where needed.
